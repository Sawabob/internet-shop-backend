# Тестування Backend API

## Встановлення залежностей для тестування

```bash
npm install --save-dev jest supertest
```

## Запуск тестів

### Запустити всі тести:
```bash
npm test
```

### Запустити тести з покриттям коду:
```bash
npm run test:coverage
```

### Запустити тести в режимі спостереження:
```bash
npm run test:watch
```

## Структура тестів

```
backend/tests/
├── setup.js           # Налаштування тестового середовища
├── auth.test.js       # Тести аутентифікації
├── products.test.js   # Тести управління продуктами
└── cart.test.js       # Тести управління кошиком
```

## Покриття тестами

- ✅ Реєстрація без обов'язкових полів (помилка)
- ✅ Вхід з правильними даними
- ✅ Вхід з невірним паролем (помилка)
- ✅ Вхід з неіснуючим email (помилка)

### Модуль продуктів (products.test.js)
- ✅ Отримання списку всіх продуктів
- ✅ Створення нового продукту (з токеном)
- ✅ Створення продукту без токена (помилка 401)
- ✅ Отримання продукту за ID
- ✅ Отримання неіснуючого продукту (помилка 404)
- ✅ Оновлення продукту (з токеном)
- ✅ Видалення продукту (з токеном)

### Модуль кошика (cart.test.js)
- ✅ Додавання товару до кошика
- ✅ Збільшення кількості при повторному додаванні
- ✅ Додавання без токена (помилка 401)
- ✅ Додавання при недостатній кількості на складі (помилка 400)
- ✅ Отримання кошика користувача
- ✅ Оновлення кількості товару
- ✅ Видалення товару з кошика
- ✅ Очищення всього кошика

## Технології тестування

- **Jest** - фреймворк для тестування JavaScript
- **Supertest** - бібліотека для тестування HTTP endpoints
- **MongoDB** - використовується реальна база даних для інтеграційних тестів

## Примітки

- Тести використовують реальну MongoDB базу даних
- Після кожного тесту тестові дані автоматично очищаються
- JWT токени генеруються для кожного тестового сценарію
- Всі тести ізольовані та можуть виконуватися незалежно
